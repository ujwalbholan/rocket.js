# Rocket.js V1 Scope

Rocket.js V1 is a small, class-oriented backend framework built on `node:net`.

Status: feature complete as of June 5, 2026.

Its purpose is to make TCP request-response internals understandable while providing enough structure for small learning applications and public demonstrations.

## Application Architecture

```text
Route
  -> Controller
  -> Service
  -> Repository
```

### Route

Routes are declared with annotations on controller methods:

```ts
@Controller("/users")
class UserController {
  @Get()
  findAll(): Response {
    return Response.json([]);
  }
}
```

### Controller

Controllers handle protocol-facing work:

- Reading request data
- Validating request input
- Calling services
- Returning responses

### Service

Services contain business logic and coordinate repositories.

### Repository

Repositories contain persistence and model-access logic. A repository may use memory, a file, or a database.

## Dependency Wiring

V1 uses manual constructor injection inside an application composition root:

```ts
class Application {
  private readonly app = new Rocket();

  constructor() {
    const repository = new UserRepository();
    const service = new UserService(repository);
    const controller = new UserController(service);

    this.app.registerController(controller);
  }

  start(): Promise<ProtocolServer> {
    return this.app.listen(3000);
  }
}

const application = new Application();
const server = await application.start();
```

Automatic dependency injection is intentionally deferred until after V1.

## Included In V1

- `Rocket` application class
- Small `Rocket` facade with separated controller and server construction logic
- Controller registration
- Controller and route annotations
- GET, POST, PUT, PATCH, and DELETE routes
- Direct route registration
- Request and response objects
- Text, JSON, empty, and custom-header response creation
- Automatic response `Content-Length`
- MiniHTTP and HTTP/1.1 response serialization
- UTF-8 byte-safe `Content-Length` framing
- Configurable request and header size limits
- Incomplete-request timeout handling
- Safe JSON request parsing
- Ordered class-based middleware objects
- Middleware short-circuiting and guarded `next()` execution
- Centralized safe error mapping
- Optional in-memory per-client rate limiting
- TCP message buffering
- MiniHTTP protocol support
- Basic browser-readable HTTP responses
- Observable asynchronous server startup
- Graceful, timeout-protected server shutdown
- Server state and bound-address inspection
- Clean npm package consumer validation
- Continuous integration release checks

## Request Safety Defaults

- Maximum request size: 1 MiB
- Maximum header size: 16 KiB
- Request completion timeout: 30 seconds
- One request and one response per TCP connection

Applications may override these values through `app.listen({ ... })`.

The default graceful shutdown timeout is 10 seconds.
